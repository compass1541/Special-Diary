# 기억의 우주(그래프 2.0) + AI 분신 — 설계

날짜: 2026-07-06
요청: "일기 3D 연결망을 체계적·시각적으로 개선 + AI를 붙여 빠르게 정보를 찾고 나를 더 잘 아는 '또 다른 나(분신)' 만들기. UX/UI·시스템 전면 변경 허용."

## 현재 상태 진단

- `src/app.js` 1,653줄 단일 클래스에 달력·편집기·인증·그래프·AI가 모두 포함 (README L3에서 분할 권장됨).
- 3D 그래프: 명시 링크(`[[ ]]`) / 공유 키워드 쌍 / 시간순 인접 3종. 문제점:
  - 키워드가 **보이지 않는 접착제** — 두 일기가 왜 연결됐는지 화면에서 알 수 없음.
  - 키워드 쌍 링크는 N² 성장 — 일기가 늘면 실타래처럼 얽힘.
  - 모든 노드에 SpriteText 라벨 상시 표시 → 노드 20개만 넘어도 시각적 소음.
  - 해시 기반 클러스터 색 → 충돌·저대비 색 발생, 클러스터 의미를 알려주는 범례 없음.
  - bloom 제거 상태라 평면적인 느낌. 레이아웃 모드 없음(force 고정).
- AI: 검색·제안 2개 액션뿐. 대화 불가, 사용자 이해(프로필) 없음.

## 접근 대안 비교

**그래프**
1. 현 구조 유지 + 라벨/색만 개선 — 근본 문제(연결 이유 불가시성) 못 풀음.
2. **[채택] 키워드 허브 2-모드 그래프**: 공유 키워드 자체를 허브 노드로 승격. 일기↔키워드 star 토폴로지로 N² 쌍 링크 제거, "왜 연결됐는가"가 구조로 보임. + bloom 글로우, 스마트 라벨, 시간 나선 레이아웃.
3. 2D 전환(Obsidian식) — 3D라는 명시 요구와 상충.

**AI 분신**
1. 매 질문마다 전체 일기 전송 — 비용·컨텍스트 한계, 스케일 불가.
2. **[채택] 로컬 TF-IDF retrieval + 프로필 캐시**: 이미 있는 `utils/keywords.js` 토크나이저 재사용. 질문과 관련된 top-K 일기만 전송. 별도 인프라 0.
3. pgvector 임베딩 DB — 마이그레이션·임베딩 파이프라인 비용 과다(YAGNI).

## 설계

### A. 모듈 분리 (이번 작업이 닿는 범위만)
```
src/graph/data.js      # 순수 함수: entries → {nodes, links, clusters, stats}  [vitest]
src/graph/view.js      # GraphView 클래스: 렌더링·bloom·레이아웃·포커스·사이드패널
src/ai/retrieval.js    # 순수 함수: (query, entries) → top-K 관련 일기        [vitest]
src/ai/persona.js      # PersonaChat: 프로필 캐시 + 대화 상태 + gemini 호출
src/ai/chatView.js     # 채팅 패널 DOM 렌더링/이벤트
```
`app.js`는 그래프/채팅 코드를 위 모듈로 위임하고 달력·편집기·인증만 유지.

### B. 그래프 2.0 — "기억의 우주"
- **노드 2종**: 일기 노드(클러스터 색, 크기=연결도) + **키워드 허브**(2개 이상 일기가 공유하는 상위 키워드, 옥타헤드론+글로우 스프라이트, 크기=연결 일기 수).
- **링크 3종**: 명시(`[[ ]]`, 밝은 청색+파티클) / 키워드(일기↔허브, 은은한 보라) / 시간순(≤30일 인접, 희미한 회색). 필터 버튼 유지(전체/명시/키워드/시간순).
- **Bloom**: `UnrealBloomPass` (strength≈1.1, threshold≈0.12). 노드+허브 300개 초과 시 기본 OFF. "✨ 글로우" 토글.
- **스마트 라벨**: 허브 라벨은 상시(소형), 일기 라벨은 선택·호버·이웃·검색 매치일 때만. "라벨 전체 보기" 토글.
- **클러스터**: 지배 키워드 기준(기존 로직), 색은 골든앵글(137.5°) 팔레트로 균등 분배. 하단에 상위 6개 클러스터 범례 칩 — 클릭 시 해당 클러스터 스포트라이트.
- **레이아웃 2모드**: 자유(force) ↔ **시간 나선**(날짜순 헬릭스에 fx/fy/fz 고정 — 일기의 시간축이 물리적 형태로 보임).
- **포커스**: 노드 클릭 → 카메라 플라이 + 이웃만 발광, 나머지 감쇠(기존 개선). ESC/배경 클릭으로 해제.
- **사이드패널 강화**: 본문 미리보기 + 키워드 칩(클릭=해당 허브 스포트라이트) + **관련 일기 목록**(공유 키워드 수 기준) + "편집기에서 열기" + **"분신에게 이 일기에 대해 묻기"**.

### C. AI 분신 — "또 다른 나"
- **진입**: 사이드바 최상단 "분신과 대화" 버튼 → 우측 슬라이드 패널(모바일은 풀스크린). 그래프 사이드패널에서도 진입 가능(일기 컨텍스트 시드).
- **retrieval.js**: 질의 토큰과 일기 토큰의 TF-IDF 가중 겹침 점수 + 최근성 부스트(감쇠 90일) + 날짜 언급 감지(질의 속 "지난달", "3월" 등은 Gemini에 맡기고 로컬은 텍스트 매칭만). top-K=12 반환.
- **프로필("분신이 이해한 나")**: Gemini `profile` 액션 → JSON `{ values, themes, emotionalPatterns, people, habits, voice, summary }`. 최근·대표 일기 최대 60개로 생성. `localStorage`에 사용자별 캐시, 지문=엔트리 수+최신 updatedAt. 채팅 패널 헤더에서 열람·수동 갱신, 지문 불일치 시 자동 재생성 제안.
- **채팅**: 시스템 프롬프트 = "너는 사용자의 일기로 구성된 또 다른 자아. 사용자의 말투·가치관을 반영, 근거 일기를 `[[YYYY-MM-DD]]`로 인용." 입력 = 프로필 + retrieval top-K + 최근 8메시지. 응답 속 `[[날짜]]`는 클릭 가능한 칩으로 렌더 → 해당 일기 열기.
- **경로**: 기존 패턴 그대로 — 로그인 시 `ai-proxy`(신규 `chat`/`profile` 액션, 동일 sanitize·rate limit), 실패 시 direct SDK 폴백. **구버전 함수가 배포된 경우**(unknown_action 400) direct 폴백 시도, 불가하면 "ai-proxy 재배포 필요" 안내.
- 프라이버시: 기존 AI 검색과 동일하게 일기 원문이 Gemini로 전송됨(신규 노출면 없음). E2EE는 기존 TODO 유지.

### D. UX/UI
- 사이드바 재편: [분신과 대화(강조 그라디언트)] / [AI 검색] / [기억의 우주(3D)] 묶음.
- 채팅: 말풍선(사용자/분신), 타이핑 인디케이터, 첫 방문 제안 칩("요즘 나 어때?", "이번 달의 나를 요약해줘", "내가 반복해서 걱정하는 건?").
- 다크 테마 유지(라이트 모드는 기존 TODO대로 범위 외). 모바일: 그래프 모달 기존 반응형 유지, 채팅 패널은 풀스크린 전환.

### E. 보안·성능·에러
- CSP 무변경(모든 라이브러리 번들). `innerHTML` 금지 규칙 준수 — 채팅 렌더는 DOM API로만.
- 프롬프트 injection sanitize 태그 목록에 신규 태그(`PROFILE`, `HISTORY`, `RETRIEVED`) 추가.
- 3D 엔진은 기존처럼 dynamic import(초기 번들 불변). bloom은 노드 수 기준 자동 강등.
- Gemini 오류·rate limit은 채팅 말풍선 안에 재시도 안내로 표기(모달 밖 toast 아님).

### F. 테스트·검증
- `src/graph/data.test.js`: 허브 승격 규칙, 링크 중복 없음, 필터/고립 카운트, 나선 좌표 단조성.
- `src/ai/retrieval.test.js`: 관련도 순위, 최근성 부스트, K 제한, 빈 질의.
- 기존 테스트(keywords/crypto/security) 회귀 없음. `npm test` + `npm run lint` + `npm run build` 그린 확인 후 dev 서버 기동 확인.

### 범위 외 (명시)
- pgvector/임베딩, 스트리밍 응답, E2EE 통합, 라이트 테마, 페이지네이션 UI.
