# 모바일 반응형 개선 설계

## 목표

최신 iPhone 및 Android 세로 화면(폭 320–430 CSS px)에서 Special Diary의 모든 주요 조작을 스크롤과 터치로 안정적으로 사용할 수 있게 한다. 데스크톱 레이아웃과 기존 기능은 바꾸지 않는다.

## 확인된 문제

- 360×800 및 320×568 목록 화면에서 캘린더 다음의 최근 일기, 새 일기, 내보내기, 가져오기 영역이 뷰포트 아래로 밀린다.
- 모바일 사이드바와 상위 앱 컨테이너가 `overflow: hidden`이어서, 화면 밖에 있는 하단 조작으로 스크롤할 수 없다.
- 고정 `100vh` 높이는 모바일 브라우저 주소창과 키보드 변화에 따라 편집기와 모달 하단을 가릴 수 있다.

## 선택한 접근

목록 화면의 모바일 사이드바를 단일 세로 스크롤 컨테이너로 전환한다. 캘린더·AI·최근 일기·백업 기능을 숨기거나 별도 하단 메뉴로 옮기지 않는다. 이 접근은 현재 정보 구조를 유지하면서 모든 조작의 도달 가능성을 복원한다.

대안으로 영역을 접거나 하단 고정 메뉴를 새로 만드는 방안도 검토했지만, 각각 기능 발견성을 낮추거나 구조적 변경 범위를 불필요하게 넓힌다.

## 구현 범위

### 목록 화면

- 모바일 전용 규칙에서 앱 및 사이드바의 높이를 동적 뷰포트 단위로 설정하고, 기존 `vh` 값을 호환용 대체값으로 유지한다.
- 목록 상태의 사이드바에 세로 스크롤과 적절한 하단 안전 영역 여백을 부여한다.
- 최근 일기 영역의 최소 높이는 유지하되, 부모 스크롤 안에서 새 일기와 백업 조작까지 접근 가능하도록 한다.
- 가로 넘침은 발생하지 않아야 한다.

### 편집기와 오버레이

- 모바일 편집기는 동적 뷰포트 높이를 사용하고 flex 자식이 축소될 수 있도록 `min-height: 0`을 유지한다.
- 편집기 하단 입력과 모달의 하단 여백에 안전 영역을 반영해 홈 인디케이터 및 주소창 변화에 가려질 가능성을 줄인다.
- 기존의 편집기 닫기, 저장, 삭제, AI 제안 동작과 그래프·채팅 패널 동작은 변경하지 않는다.

### 접근성과 상호작용

- 모바일 전용 터치 조작은 최소 44px 목표 크기에 맞춰 점검하고, 작은 조작은 필요한 범위에서 보완한다.
- 목록은 하나의 예측 가능한 스크롤 경로를 제공하며, 데스크톱의 분할 레이아웃에는 영향을 주지 않는다.

## 검증

- CSS의 모바일 뷰포트 및 스크롤 규칙을 대상으로 자동화된 회귀 테스트를 추가한다.
- Vitest 전체, ESLint, 프로덕션 빌드를 실행한다.
- 실제 브라우저에서 320×568, 360×800, 430px급 세로 뷰포트를 확인한다.
- 각 목록 화면에서 가로 넘침이 없고, 새 일기·내보내기·가져오기 버튼이 스크롤을 통해 도달 가능한지 측정한다.
- 편집기에서 하단 입력이 뷰포트 안에 있고, 그래프 모달의 본문과 사이드 패널이 모두 보이는지 확인한다.

## 비범위

- 정보 구조 재설계, 하단 탭 바 도입, 기능 제거는 포함하지 않는다.
- 데이터 저장, 인증, AI, 그래프의 비주얼 디자인과 비즈니스 로직은 변경하지 않는다.
